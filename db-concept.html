📘 DB Concept — ความรู้พื้นฐานด้านฐานข้อมูล

คะแนน 10 โจทย์เขียนตอบ: นิยาม + ตัวอย่าง อ่านก่อนบทอื่น เพราะเป็นฐานของทุกหัวข้อ

📝 หัวข้อนี้ออกสอบยังไง

จากรีวิวรุ่นพี่ ข้อสอบพื้นฐานมักเป็นคำถามสั้น ๆ ประมาณ "X คืออะไร จงอธิบายพร้อมยกตัวอย่าง" สูตรตอบให้คะแนนเต็มคือ นิยาม 1–2 บรรทัด → ยกตัวอย่างจริง 1 ตัว เท่านั้น ไม่ต้องเขียนยาว

1. ฐานข้อมูล (Database) คืออะไร

ฐานข้อมูล (Database) คือ คลังหรือกลุ่มของข้อมูลที่มีความสัมพันธ์กัน (Related Data) ซึ่งถูกนำมารวบรวมและจัดเก็บไว้อย่างเป็นระบบในสื่อจัดเก็บข้อมูลถาวร เพื่อให้ผู้ใช้หรือแอปพลิเคชันสามารถเข้าถึง จัดการ ค้นหา และดึงข้อมูลไปใช้ได้อย่างมีประสิทธิภาพ

🔍 เปรียบเทียบให้เห็นภาพ

ฐานข้อมูลเหมือน ตู้เอกสารของสำนักงาน — ข้อมูลไม่ได้ทิ้งกองรวม ๆ ไว้ในกล่องเดียว แต่ถูกแยกเป็นแฟ้ม (ตาราง) ตามหมวดหมู่ เช่น แฟ้มนักศึกษา แฟ้มอาจารย์ แฟ้มวิชาเรียน และแต่ละแฟ้มอ้างอิงถึงกันได้ (รหัสวิชาในใบลงทะเบียน ชี้ไปยังแฟ้มวิชา)

ข้อมูลที่จัดเก็บมี 3 แบบ

🧱 Structured Data

โครงสร้างชัดเจน แน่นอน เก็บเป็นตาราง (แถว/คอลัมน์) เช่น รหัสนักศึกษา ชื่อ เงินเดือน

📄 Unstructured Data

ไม่มีโครงสร้างแน่นอน เช่น คอมเมนต์ข้อความ รูปภาพ เสียง วิดีโอ

🧩 Semi-Structured

โครงสร้างยืดหยุ่น เช่น ไฟล์ JSON, XML — มีโครงแต่ปรับได้

ตัวอย่างฐานข้อมูลที่ใช้ตอบข้อสอบได้: ระบบลงทะเบียนเรียนของนักศึกษา, ระบบจองตั๋วหนัง, ระบบประวัติพนักงาน, ระบบสต็อกสินค้า

2. ระบบจัดการฐานข้อมูล (DBMS) คืออะไร

DBMS (Database Management System) คือ ซอฟต์แวร์ที่ทำหน้าที่เป็นตัวกลาง ในการบริหารจัดการฐานข้อมูล — ควบคุมการเข้าถึง จัดเก็บ แก้ไข ค้นหาข้อมูล และรักษาความปลอดภัยของข้อมูล ระหว่างผู้ใช้/แอปพลิเคชันกับไฟล์ฐานข้อมูลจริงในดิสก์

🔍 เปรียบเทียบให้เห็นภาพ

ถ้าฐานข้อมูลคือ ตู้เอกสาร DBMS ก็คือ นายทะเบียน/ภารโรงเจ้าของตู้ — เราไม่ได้เข้าไปจับแฟ้มเอง แต่ยื่นคำขอให้เขาหยิบ เพิ่ม แก้ หรือลบให้ พร้อมตรวจว่าเรามีสิทธิ์หรือไม่ และเก็บประวัติการทำงานทุกอย่างไว้เสมอ

3. Key ทุกชนิด — หัวใจของตาราง

Key ใช้สำหรับ ระบุแถวข้อมูลให้เจาะจงไม่ซ้ำ และ สร้างความสัมพันธ์ระหว่างตาราง ซึ่งเป็นพื้นฐานที่ Normalization (40 คะแนน) ต้องใช้เยอะมาก

ภาพที่ 3: ลำดับชั้น Super Key → Candidate Key → Primary/Alternate Key

🧩 Composite Key

PK ที่ใช้ ตั้งแต่ 2 คอลัมน์ขึ้นไปรวมกัน เช่น ตาราง Work_On ใช้ (Emp_ID, Proj_ID) เพราะตัวใดตัวเดียวไม่พอระบุแถว (พนักงาน 1 คนทำได้หลายโปรเจกต์)

🔗 Foreign Key (FK)

คอลัมน์ในตาราง A ที่ อ้างอิงไปยัง PK ของตาราง B เพื่อสร้างความสัมพันธ์และคุมกฎความถูกต้อง (Referential Integrity) เช่น Dept_ID ในตารางพนักงาน → ชี้ไปที่ตารางแผนก

4. ความซ้ำซ้อน (Redundancy) และ Anomalies 3 ปัญหา

Data Redundancy คือ การเก็บข้อมูลเรื่องเดียวกันซ้ำ ๆ หลายแห่ง ทำให้เสียพื้นที่ และเกิดความผิดปกติ (Anomalies) 3 ประการ:

➕ Insertion Anomaly

เพิ่มไม่ได้ — จะเพิ่มแผนกใหม่ได้ยังไง ถ้ายังไม่มีพนักงานสังกัดเลย (คอลัมน์ PK พนักงานต้องมีค่า)

➖ Deletion Anomaly

ลบแล้วเสียข้อมูลอื่น — ลบพนักงานคนสุดท้ายของแผนก A ทิ้ง ข้อมูลแผนก A ก็หายไปด้วยเลย

✏️ Update Anomaly

แก้หลายจุด — ชื่อแผนกซ้ำอยู่ 50 แถว ต้องแก้ 50 จุด แก้ไม่ครบข้อมูลขัดแย้งกันทันที

🧠 วิธีจำ

I-D-U = Insert เพิ่มไม่ได้ / Delete ลบแล้วพัง / Update แก้ไม่จบ — และทางแก้คือ Normalization (แตกตารางให้ข้อมูลแต่ละเรื่องเก็บที่เดียว)

ภาพที่ 5: สถาปัตยกรรม 3-Tier — ผู้ใช้ → โปรแกรมกลาง → ฐานข้อมูล

ประโยชน์ของระบบฐานข้อมูล (ตอบข้อสอบได้): ลดความซ้ำซ้อน (Minimum Redundancy) • รักษาความถูกต้อง (Data Integrity) ด้วย Entity Integrity และ Referential Integrity • ใช้ข้อมูลร่วมกันได้ (Data Sharing & Concurrent Access) • ควบคุมความปลอดภัย (Security & Authorization) • เกิดความเป็นอิสระของข้อมูล (Data Independence)

6. Schema vs Instance — คู่ที่สอบชอบถาม

ประเด็นDatabase SchemaDatabase Instance
คืออะไรโครงสร้าง/พิมพ์เขียว (Blueprint) — ชื่อตาราง ชื่อคอลัมน์ ชนิดข้อมูล กฎเกณฑ์ข้อมูลจริงที่อยู่ในตาราง ณ เวลาหนึ่ง
เปลี่ยนไหมแทบไม่เปลี่ยน (ออกแบบครั้งเดียว)เปลี่ยนตลอดเวลาเมื่อมี INSERT / UPDATE / DELETE

7. Data Independence — ความเป็นอิสระของข้อมูล 2 ระดับ

🧠 Logical Data Independence

แก้โครงสร้างเชิงตรรกะ (เช่น เพิ่มคอลัมน์ใหม่ในตาราง) โดยโปรแกรม/มุมมองผู้ใช้ไม่พัง

💾 Physical Data Independence

เปลี่ยนวิธีจัดเก็บเชิงกายภาพ (เช่น เพิ่ม Index, เปลี่ยน Storage) โดยโครงสร้างตารางเชิงตรรกะไม่กระทบ

🧠 วิธีจำไม่สลับ

Logical = โครงตารางเปลี่ยน โปรแกรมรอด | Physical = ที่เก็บเปลี่ยน โครงตารางรอด — คำที่อยู่หน้าชื่อ = "สิ่งที่เปลี่ยน"

8. ภาษา SQL แบ่งเป็น 4 กลุ่ม

🏗️ DDL — Data Definition Language

จัดการโครงสร้าง (สร้าง/แก้/ลบตาราง)
CREATEALTERDROPTRUNCATE

✏️ DML — Data Manipulation Language

จัดการข้อมูลภายในตาราง
SELECTINSERTUPDATEDELETE

🔐 DCL — Data Control Language

ควบคุมสิทธิ์การเข้าถึง
GRANTREVOKE

⏯️ TCL — Transaction Control Language

ควบคุมTransaction
COMMITROLLBACKSAVEPOINT

⚠️ ข้อควรระวังที่ข้อสอบชอบหลอก

TRUNCATE และ DROP เป็น DDL! ไม่ใช่ DML — และเพราะเป็น DDL มันจะ Auto-Commit ทันที สั่ง ROLLBACK คืนไม่ได้ (เกี่ยวโยงกับบท Recovery ด้วย)

ตัวอย่างที่ 1: Dept-Emp (Live 0004–0005) — ตัวอย่างคลาสสิกที่ต้องเก่งที่สุด

ภาพ ER 1: Dept-Emp — จุดเด่น: Employee–Department มีความสัมพันธ์ 2 เส้นแยกกัน (สังกัด 1:N / จัดการ 1:1) และ Supervise เป็น Recursive

⚠️ กับดักที่อาจารย์เน้น (โจทย์ออกแนวนี้)

  • ห้ามรวม 2 เส้น Work_In (สังกัด 1:N แบบ Total) กับ Manages (จัดการ 1:1 แบบ Partial) — ลอจิกต่างกัน
  • Location ของแผนกเป็น Multivalued (วงกลมซ้อน 2 วง) — Map เป็นตารางต้องแยก Dept_Location ออกมา (กัน 1NF พัง)
  • Hours ต้องแขวนที่ความสัมพันธ์ Work_On (M:N) — ห้ามแปะที่ Employee หรือ Project เดี่ยว ๆ เพราะเป็นค่าที่เกิดจากการจับคู่
  • Supervise (หัวหน้า–ลูกน้อง) บน Entity ตัวเอง → ตอน Map จะได้ FK ชี้กลับ PK ของตารางตัวเอง (Super_Emp_ID)
  • Dependent เป็น Weak Entity — มีแค่ Partial Key (Dependent_Name) ต้องพึ่ง PK ของ Employee

ภาพ ER 2: Food and Drink — ต้องมี Receipt คั่นกลางระหว่าง Customer กับ Product เสมอ (บนความสัมพันธ์ M:N มี Qty, Price, Discount)

⚠️ กับดัก 3 ข้อที่นักศึกษาตกบ่อยสุด

  • ห้ามลากเส้น Customer → Product ตรง ๆ — ลูกค้าจะซื้อของชิ้นเดียวกันได้แค่ครั้งเดียวในชีวิต! ต้องมี Receipt คั่นกลางเพื่อเก็บประวัติซื้อซ้ำได้
  • ห้ามแยก Entity ตามประเภทสินค้า (อาหารตาราง, เครื่องดื่มอีกตาราง) — พอมีประเภทใหม่ DB พัง ให้รวมเป็น Product เดียว + Product_Type จำแนก
  • ห้ามแยก สมาชิก/ลูกค้าทั่วไป เป็น 2 Entity — ใช้ Customer เดียว + Attribute Discount_Pct จำแนก (คนทั่วไป = 0%)

ภาพ ER 3: BOM — "ชุดเซ็ตก็คือสินค้าตัวหนึ่ง" ที่มีสูตรประกอบ (M:N กับตัวเอง) เช่น ชุด A ประกอบจากแก้ว + กาแฟ + น้ำตาล

📝 แนวข้อสอบ DB Concept + ตัวอย่างคำตอบ

5 คำถามคลาสสิกที่ออกซ้ำทุกปี — ลองเขียนตอบเองก่อนแล้วกดดูเฉลย

ข้อ 1: ฐานข้อมูล (Database) คืออะไร พร้อมยกตัวอย่าง

ฐานข้อมูล คือ คลัง/กลุ่มของข้อมูลที่มีความสัมพันธ์กัน (Related Data) ซึ่งรวบรวมและจัดเก็บอย่างเป็นระบบในสื่อจัดเก็บถาวร เพื่อให้เข้าถึง จัดการ ค้นหา และใช้งานได้อย่างมีประสิทธิภาพ — ตัวอย่าง: ระบบฐานข้อมูลการลงทะเบียนเรียนของมหาวิทยาลัย ซึ่งเก็บข้อมูลนักศึกษา วิชาเรียน และผลการลงทะเบียนที่สัมพันธ์กัน

ข้อ 2: ระบบจัดการฐานข้อมูล (DBMS) คืออะไร พร้อมยกตัวอย่าง

DBMS คือ ซอฟต์แวร์ที่ทำหน้าที่เป็นตัวกลางบริหารจัดการฐานข้อมูล — ควบคุมการเข้าถึง จัดเก็บ แก้ไข ค้นหา และรักษาความปลอดภัยของข้อมูลระหว่างผู้ใช้กับไฟล์ฐานข้อมูลจริง — ตัวอย่าง: Oracle, MySQL, SQL Server, PostgreSQL, MongoDB

ข้อ 3: Transaction คืออะไร พร้อมยกตัวอย่าง

Transaction คือ กลุ่มคำสั่ง DML หลายคำสั่งที่ทำงานต่อเนื่องกันเป็นหน่วยงานเชิงตรรกะเดียว (Logical Unit of Work) ซึ่งต้องสำเร็จทั้งหมดหรือล้มเหลวทั้งหมด (All or Nothing) — ตัวอย่าง: การโอนเงิน 1,000 บาท ประกอบด้วย ตรวจยอด → หักเงินบัญชี A → เพิ่มเงินบัญชี B → บันทึกสลิป ต้องสำเร็จครบทุกขั้น ถ้าพลาดขั้นใดต้องยกเลิกทั้งหมด

ข้อ 4: Recovery Control คืออะไร พร้อมยกตัวอย่าง

Recovery Control คือ กลไกของ DBMS ในการคืนสภาพฐานข้อมูลกลับสู่สถานะถูกต้องสมบูรณ์ (Consistent State) เมื่อเกิดความล้มเหลว เช่น ไฟดับ ระบบล่ม — ตัวอย่าง: ระบบดับกลางการโอนเงินหลังหักบัญชี A แต่ก่อนเพิ่มบัญชี B เมื่อระบบกลับมา Log จะทำ UNDO คืนเงินเข้าบัญชี A ให้เหมือนไม่เคยทำรายการ

ข้อ 5: Concurrency Control คืออะไร พร้อมยกตัวอย่าง

Concurrency Control คือ กลไกของ DBMS ในการควบคุมให้หลาย Transaction ที่ทำงานพร้อมกัน ได้ผลลัพธ์เสมือนทำงานทีละตัวตามลำดับ (Serializable) โดยไม่รบกวนกัน — ตัวอย่าง: ระบบจองตั๋วหนังที่มีคนจองที่นั่งเดียวกันพร้อมกัน 200 คน ต้องมีระบบ Lock กันขายที่นั่งเดิมให้สองคน

Q1ข้อใดคือคุณสมบัติของ Primary Key?

เฉลย ข้อ 3 — PK ต้อง Unique + Not Null เสมอ ส่วนชนิดข้อมูลเป็นอะไรก็ได้ (ตัวเลข ตัวอักษร ฯลฯ)

Q2คอลัมน์ Dept_ID ในตาราง EMPLOYEE ที่ชี้ไปยัง PK ของตาราง DEPARTMENT เรียกว่าอะไร?

เฉลย ข้อ 2 — คอลัมน์ที่อ้างอิง PK ของตารางอื่นเรียกว่า Foreign Key (FK) ใช้สร้างความสัมพันธ์และคุม Referential Integrity

Q3ลบพนักงานคนสุดท้ายของแผนกแล้วข้อมูลแผนกหายไปด้วย เป็นปัญหาอะไร?

เฉลย ข้อ 1 — การลบแถวหนึ่งแต่ทำให้ข้อมูลสำคัญอื่น (ข้อมูลแผนก) สูญหายไปด้วย คือ Deletion Anomaly ซึ่งแก้ด้วยการทำ Normalization
